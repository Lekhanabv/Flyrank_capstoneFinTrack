# Reflection

The hardest part of building FinTrack AI was balancing product polish with technical reliability. As a frontend capstone, the biggest challenge was not just creating a visually strong finance dashboard, but making sure the app felt trustworthy and useful rather than like a static mockup. I wanted the experience to feel realistic, responsive, and informative, while also integrating AI in a way that could gracefully handle failure. Designing the user experience around financial clarity, data hierarchy, and decision support required careful attention to both usability and engineering constraints.

I implemented the AI-powered financial insights by creating a server-side route in the Next.js app that receives a structured financial payload from the client, validates it, and sends it to OpenRouter. The route includes environment-based configuration for the API key and model, normalizes the data, and formats the request so the model can return actionable financial guidance. The response is parsed into a predictable JSON structure containing summary, budgeting advice, spending trends, savings recommendations, unusual expenses, and next steps. On the frontend, I built the insights panel to load asynchronously, show a loading state, display retry actions, and fall back to safe default insight content when the AI service is unavailable or returns malformed data. This approach helped keep the app usable even when external services fail, which is especially important for a demo or production-like product.

During this project, I learned a great deal about how frontend development and AI integration need to work together in practice. I gained a better understanding of how important state management, loading states, and user feedback are for perceived reliability. I also learned that AI features are most valuable when they are grounded in clear, structured input and when the system is engineered to degrade gracefully. In addition, working on a real finance dashboard helped me appreciate the importance of strong visual hierarchy, mobile responsiveness, and building interfaces that make complex information easier to interpret.

In the future, I would improve FinTrack AI by adding real authentication, persistent data storage, and connected financial sources such as CSV imports or banking APIs. I would also expand the insight model to support personalized goals, forecasting, and more advanced anomaly detection. A stronger testing strategy, including route tests, component tests, and end-to-end validation, would make the product more reliable and easier to maintain. Overall, this project taught me that the strongest AI product experiences are not simply “smart,” but also clear, resilient, and grounded in real user needs.
